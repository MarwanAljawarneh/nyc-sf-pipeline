# NYC vs SF Cost & Quality of Life Pipeline

A daily ELT pipeline that compares New York City and San Francisco across weather, housing, and cost of living — orchestrated with Apache Airflow, warehoused in PostgreSQL (Supabase), transformed with dbt, and visualized in a live Streamlit dashboard.

---

## Architecture

```
Open-Meteo API  ──┐
Zillow ZORI CSV ──┼──▶ Airflow (Docker) ──▶ Supabase (Postgres) ──▶ dbt ──▶ Streamlit
BLS CPI API     ──┘
```

## Tech Stack

| Layer | Tool |
|---|---|
| Orchestration | Apache Airflow (Docker) |
| Extraction | Python, Requests, Polars |
| Warehouse | Supabase (PostgreSQL) |
| Transformation | dbt Core |
| Dashboard | Streamlit |
| Dependency Management | uv |
| Logging | Loguru |

## Data Sources

| Source | Data | Frequency |
|---|---|---|
| [Open-Meteo](https://open-meteo.com/) | Daily temperature & precipitation | Daily |
| [Zillow ZORI](https://www.zillow.com/research/data/) | Median observed rent | Monthly |
| [BLS CPI API](https://www.bls.gov/developers/) | Consumer Price Index | Monthly |

## Setup

### Prerequisites
- Docker Desktop
- Python 3.12+
- uv

### Installation

1. Clone the repo
```bash
git clone git@github.com:MarwanAljawarneh/nyc-sf-pipeline.git
cd nyc-sf-pipeline
```

2. Install dependencies
```bash
uv sync
```

3. Create a `.env` file in the root directory with the following variables:
```
SUPABASE_DB_URL=postgresql://...
BLS_API_KEY=your_bls_api_key
```

4. Start Airflow
```bash
cd airflow-practice
docker-compose up -d
```

5. Open Airflow UI at `http://localhost:8080`

## ETL code organization

Reusable extraction and loading functions live in the `nyc_sf_pipeline/` Python
package (`weather.py`, `cpi.py`, and `housing.py`). The `scripts/` files
are small compatibility entry points so existing Airflow DAGs can keep their
current imports and task IDs.

Run an extractor locally from the project root with:

```bash
uv run python -m scripts.extract_weather
uv run python -m scripts.extract_cpi
uv run python -m scripts.extract_housing
```

Each loader still requires `SUPABASE_DB_URL` and uses an atomic transaction
for the whole batch. The existing GitHub Actions workflow uses mocked API and
database tests and does not write to your production database.

This is a Python module/package reorganization, not a change to Airflow deployment
or its mount configuration. Ensure the repository root is available on Airflow's
Python path (as with the existing `/opt/airflow` setup).
